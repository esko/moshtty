## 2024-05-24 - Avoid querySelector on hot paths
**Learning:** Using `document.querySelector("dialog[open]")` inside a keydown listener is very slow because querySelector forces the browser to parse the selector and traverse the DOM on every key press. Checking properties directly on cached DOM element references (like `renameDialog.open || profileDialog.open ...`) or using a live `HTMLCollection` from `document.getElementsByTagName("dialog")` is approximately ~100x faster in JS and avoids the query overhead. Since the terminal application captures keystrokes constantly, removing this bottleneck in `shouldHandleAppShortcut` improves overall keystroke latency significantly.
**Action:** When an element's state needs to be checked on every keystroke, cache the DOM node references or live HTMLCollections during initialization and check their properties directly rather than using CSS selectors like querySelector.
