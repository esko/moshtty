## 2024-06-25 - Avoid unsafe slice reuse in Go
**Learning:** Reusing read buffers and passing them by reference (`chunk := buf[:n]`) without explicit copying (`append([]byte(nil), buf[:n]...)`) in a Go I/O loop is an anti-pattern. If downstream consumers like `capture` store that data or asynchronous broadcasters hold a reference, the underlying array will be overwritten by the next `Read()` iteration causing catastrophic data corruption. In Go, explicit heap copies are almost always necessary for correctness when dealing with buffered I/O streams unless you explicitly control all synchronous consumers.
**Action:** Do not try to remove memory copies in Go I/O loops. For hot path array iteration in TypeScript/JavaScript, instead prefer traditional index-based loops (`for (let i = 0...)`) over closures (`reduce`) and iterables (`for...of`) to reduce GC pressure for very tight loops.
